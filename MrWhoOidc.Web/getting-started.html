Prebuilt image guide

Install MrWhoOidc from the published Docker image.

Set up a local instance with PostgreSQL and create your first tenant. Docker and Git are required; the first run downloads the container images.

Prerequisites

Docker & Docker Compose

Docker Desktop or Docker Engine with Compose V2. If you only have docker-compose, substitute that command below.

Git

To clone the public deployment repository.

Memory

4 GB RAM recommended for the database and supporting containers.

Disk Space

Roughly 2-3 GB free for images, layers, and local data.

Use the deployment repository: these commands expect MrWho, not the MrWhoOidc source tree. Keep the working directory outside /tmp so configuration survives cleanup. Use docker compose up -d as shown; adding --build is not part of the published-image setup.
Behind a reverse proxy with TLS termination? If public HTTPS is handled upstream and you do not want a local certificate inside the backend container, use the Proxy TLS Termination track instead of this page.

To change or debug the code, use the source-build guide instead.

1

Create A Work Folder, Clone, And Configure

Use a persistent working directory, not /tmp. Clone the public deployment repo, run the dev-setup script to generate the local certificate and environment file.

mkdir -p "$HOME/src"
cd "$HOME/src"

git clone https://github.com/popicka70/MrWho.git
cd "$HOME/src/MrWho"

# Generate a local HTTPS dev certificate, trust it, and create .env
bash scripts/setup-dev.sh          # Linux/macOS
# pwsh scripts/setup-dev.ps1       # Windows

# Linux/macOS: keep the mounted PFX readable by the container user
# (setup-dev.sh already does this; shown here in case you created the cert manually)
chmod 644 ./certs/aspnetapp.pfx

test -f ./certs/aspnetapp.pfx && echo "certificate ready"

# Fallback only (the setup script already creates .env):
# cp .env.example .env
grep -q 'ghcr.io/popicka70/mrwhooidc:latest' ./docker-compose.yml && echo "published image compose file confirmed"
About the setup script: it generates certs/aspnetapp.pfx locally with password changeit, trusts the certificate so browsers don't warn, and creates .env from .env.example with development defaults. The dev certificate is generated locally and is NOT committed to the repository — each developer runs the setup script to generate their own cert. It is idempotent and never overwrites an existing .env.
Linux note: if startup fails with Access to the path '/https/aspnetapp.pfx' is denied, run chmod 644 ./certs/aspnetapp.pfx again and restart the stack.

Open .env and set:

  • POSTGRES_PASSWORD — database password
  • CERT_PASSWORD — changeit (matches the cert generated by scripts/setup-dev.sh / scripts/setup-dev.ps1)
  • OIDC_PUBLIC_BASE_URL — https://localhost:8443
  • BOOTSTRAP_TOKEN — temporary-bootstrap-token for first-time setup on an empty database
Reusing local Docker state? PostgreSQL only applies POSTGRES_PASSWORD when the data directory is first initialized. If you have run this stack before and changed the password, either keep the previous value or reset local state with docker compose down -v --remove-orphans before continuing.

The repo expects the certificate at certs/aspnetapp.pfx. Run every remaining command from $HOME/src/MrWho. See certs/README.md for certificate details.

Wrong commands for this page: git clone https://github.com/popicka70/MrWhoOidc.git, cd /tmp, docker compose -f docker-compose.yml up -d --build.

Start & Bootstrap

Start the published-image stack from the MrWho repository, wait for WebAuth to finish starting, then bootstrap your first tenant.

docker compose config | grep ghcr.io/popicka70/mrwhooidc:latest
docker compose up -d

    curl -k -X POST https://localhost:8443/bootstrap \
      -H "Content-Type: application/json" \
            -H "X-Bootstrap-Token: temporary-bootstrap-token" \
      -d '{
        "tenantSlug": "default",
        "tenantName": "Default Tenant",
        "adminEmail": "admin@example.com",
        "adminPassword": "ChangeMeNow123!",
        "adminName": "Administrator"
      }'

The first command must print ghcr.io/popicka70/mrwhooidc:latest. If it does not, stop because you are not using the published image path. On the first run, WebAuth can take a few extra seconds to bind HTTPS after docker compose up -d. If the first bootstrap curl fails with a TLS or socket error, wait 5-10 seconds and retry the same request.

With the stock .env.example, Compose may warn that MAIL_SMTP_HOST, MAIL_FROM_ADDRESS, MAIL_SMTP_USERNAME, and MAIL_SMTP_PASSWORD are unset. Those warnings are expected on first run and are non-blocking unless you plan to enable SMTP.

Important: After bootstrap, remove BOOTSTRAP_TOKEN from .env and restart with docker compose up -d. A short warm-up after that restart is normal before the smoke tests return 200/302 again.
3

Verify

Confirm the installation with these smoke tests. If you just removed BOOTSTRAP_TOKEN and restarted, give the container a few seconds to finish warming up first.

# Tenant-scoped discovery (should return JSON configuration)
    curl -k https://localhost:8443/t/default/.well-known/openid-configuration

    # Admin UI (should redirect to tenant login page)
    curl -k -I https://localhost:8443/admin/clients

    # Tenant JWKS (should return signing keys)
    curl -k https://localhost:8443/t/default/jwks

Discovery should include issuer, authorization_endpoint, token_endpoint, and jwks_uri.

Install the CLI AI-native

Install mrwho-cli to manage tenants, clients, and users from the terminal or an AI agent.

# Requires .NET 10 SDK or later
dotnet tool install --global MrWhoOidc.Cli

# Log in via device-code flow
mrwho-cli login --server https://localhost:8443/t/default
Note: mrwho-cli login is interactive device-code authentication. It waits for you to complete the browser/login flow, so treat it as a manual follow-up step rather than a fire-and-forget terminal command.

AI-native & LLM-ready

mrwho-cli includes built-in MCP support. Run mrwho-cli mcp to expose admin operations as structured tools for VS Code Copilot, Claude Desktop, or any MCP-compatible agent.

The CLI help is written to guide a complete OIDC setup: tenant creation, client registration, and token validation.

Package on NuGet: nuget.org/packages/MrWhoOidc.Cli

Troubleshoot Quickly

Most first-run issues come from Docker not running, slow startup, or busy local ports.

  • If port 8443 is busy, stop the conflicting process or remap the published port in .env.
  • If you accidentally cloned into /tmp, stop and re-clone into a persistent directory such as $HOME/src.
  • If ./certs/aspnetapp.pfx is missing, rerun bash scripts/setup-dev.sh (Linux/macOS) or pwsh scripts/setup-dev.ps1 (Windows) to regenerate it.
  • If startup fails with Access to the path '/https/aspnetapp.pfx' is denied on Linux, run chmod 644 ./certs/aspnetapp.pfx and restart the stack.
  • If mrwho-oidc logs show password authentication failed for user "oidc" and PostgreSQL says initialization was skipped, you are reusing an older local database volume. Restore the old password or run docker compose down -v --remove-orphans, then start again.
  • If the first bootstrap curl fails right after docker compose up -d, wait a few seconds for WebAuth to finish starting and retry the same request.
  • If the stack looks stuck, wait for the initial image pulls and migrations to finish, then re-run docker compose ps.
  • If the post-bootstrap restart was recent, give WebAuth 10-30 seconds to warm up before retrying the smoke-test curls.
  • If Compose warns about unset MAIL_* variables on the first run, you can ignore that noise unless you are configuring SMTP.
  • If Docker is unavailable, start the daemon first and retry.

What to expect

  • This page uses the published-image docker-compose.yml flow from the MrWho repository.
  • The admin URL redirects anonymous users to the tenant login page — this is expected behavior.
  • The strongest first smoke test is tenant-scoped discovery.
  • After removing BOOTSTRAP_TOKEN, POST /bootstrap returns 404.
