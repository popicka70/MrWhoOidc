Installation guide

Get MrWhoOidc running locally.

This page covers the public Docker deployment path. Estimated time: 3-5 minutes on a typical machine.

Prerequisites

Docker & Docker Compose

Docker Desktop or Docker Engine with the Compose V2 plugin. If you only have docker-compose, substitute that command name in the examples below.

Git

To clone the public deployment repository.

Memory

4 GB RAM recommended so the database and supporting containers start comfortably.

Disk Space

Plan for roughly 2-3 GB of free disk space for images, layers, and local data.

This guide uses the public source repository. If you want the fastest seeded local development workflow, start with docker-compose.dev.yml from the same repo.
1

Clone & Configure

Clone the source repository, generate a TLS certificate for localhost, and create your environment file.

git clone https://github.com/popicka70/MrWhoOidc.git
cd MrWhoOidc

bash ./scripts/generate-cert.sh localhost changeit
cp .env.example .env

Open .env and set these values:

  • POSTGRES_PASSWORD — database password
  • CERT_PASSWORD — changeit (matches the cert generation)
  • OIDC_PUBLIC_BASE_URL — https://localhost:8443
  • BOOTSTRAP_TOKEN — a temporary secret for first-time setup (any strong string)
2

Start & Bootstrap

Start the stack with Docker Compose, then bootstrap your first tenant.

docker compose up -d

curl -k -X POST https://localhost:8443/bootstrap \
  -H "Content-Type: application/json" \
  -H "X-Bootstrap-Token: ${BOOTSTRAP_TOKEN}" \
  -d '{
    "tenantSlug": "default",
    "tenantName": "Default Tenant",
    "adminEmail": "admin@example.com",
    "adminPassword": "ChangeMeNow123!",
    "adminName": "Administrator"
  }'
Important: After bootstrap, remove BOOTSTRAP_TOKEN from .env and run docker compose up -d again. The bootstrap endpoint should no longer be available.
3

Verify

Confirm your installation is working with these smoke tests.

# Tenant-scoped discovery (should return JSON configuration)
curl -k https://localhost:8443/t/default/.well-known/openid-configuration

# Admin UI (should redirect to tenant login page)
curl -k -I https://localhost:8443/admin/clients

# Tenant JWKS (should return signing keys)
curl -k https://localhost:8443/t/default/jwks

Expected discovery fields include issuer, authorization_endpoint, token_endpoint, and jwks_uri.

4

Install the CLI AI-native

Install mrwho-cli — a .NET global tool available on NuGet.org — to manage tenants, clients, users, and more from the terminal or from an AI agent.

# Requires .NET 10 SDK or later
dotnet tool install --global MrWhoOidc.Cli

# Log in via device-code flow
mrwho-cli login --server https://localhost:8443/t/default

AI-native & LLM-ready

mrwho-cli includes built-in MCP (Model Context Protocol) support. Run mrwho-cli mcp to start a JSON-RPC stdio server that exposes every admin operation as a structured tool — ready to wire directly into VS Code Copilot, Claude Desktop, or any MCP-compatible agent.

The CLI's help text and command descriptions are written to guide LLMs through a complete OIDC IdP setup: from tenant creation to client registration to token validation — no hand-holding required.

Package on NuGet: nuget.org/packages/MrWhoOidc.Cli

5

Explore

You're up and running. Here's what to do next:

  • Log into the Admin UI at https://localhost:8443/admin with the credentials from bootstrap.
  • Create OIDC clients and configure scopes for your applications.
  • Try the example applications (Blazor, Razor, React, Go) in the repo's Examples/ directory.
  • Use the CLI tool (mrwho-cli) for scripted tenant and client administration.
  • Run the health check script: bash ./scripts/health-check.sh
6

Troubleshoot Quickly

Most first-run issues come from Docker not running yet, startup taking longer than expected, or local ports already being used.

  • If port 8443 is busy, stop the conflicting process or remap the published port in .env.
  • If the stack looks stuck, wait for the initial image pulls and migrations to finish, then re-run docker compose ps.
  • If Docker is unavailable, start the daemon first and retry.

What to expect

  • The admin URL redirects anonymous users to the tenant login page — this is expected behavior.
  • The strongest first smoke test is tenant-scoped discovery.
  • After removing BOOTSTRAP_TOKEN, POST /bootstrap returns 404.
