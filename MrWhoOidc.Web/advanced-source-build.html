Advanced guide

Build MrWhoOidc from source.

Build local images and run the development stack for debugging or contributing changes. The first build takes longer while dependencies and base images are downloaded.

When To Use This Page

Use this page when

You need to modify code, debug the product, run sample apps, or build local Docker images from the checked-out source tree.

Not sure which path you need?

If you only want the published Docker image path, or you need Redis and examples without changing source, start from the deployment chooser instead.

Open the deployment path chooser
Development setup: this guide builds local images and starts a stack with seeded test data. For the published image, use the Docker installation guide.

The source build uses the MrWhoOidc repository and its development Compose file. The MrWho repository and POST /bootstrap belong to the published-image installation, not this seeded development stack.

Prerequisites

Docker & Docker Compose

Docker Desktop or Docker Engine with Compose V2. This workflow builds local images.

Git

To clone the source repository into a persistent working directory.

.NET 10 SDK

Required for AppHost, local debugging, tests, and some contributor workflows.

Disk Space

Plan for roughly 5 GB free disk space because this workflow builds multiple local images.

1

Create A Work Folder And Clone The Source Repository

Use a persistent working directory, not /tmp. Run every remaining command from $HOME/src/MrWhoOidc.

mkdir -p "$HOME/src"
cd "$HOME/src"
pwd

git clone https://github.com/popicka70/MrWhoOidc.git
cd "$HOME/src/MrWhoOidc"
pwd

test -f docker-compose.dev.yml && test -f .env.example && test -d MrWhoOidc.WebAuth && echo "MrWhoOidc source repo ready"

Expected result: the final command prints MrWhoOidc source repo ready.

2

Create The Local Environment File

The source-built development stack usually works with the default development values.

cp .env.example .env
test -f .env && echo ".env ready"

Edit .env only if you need to override defaults for advanced testing.

3

Build And Start The Seeded Development Stack

This workflow builds local Docker images from the checked-out source tree.

docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml ps

Expected result: Docker builds local images, then starts WebAuth, PostgreSQL, Redis, MailHog, and the sample applications.

4

Verify The Seeded Development Tenant

The development stack auto-seeds the default tenant. Do not call /bootstrap on this page.

curl -k https://localhost:8443/t/default/.well-known/openid-configuration
bash ./scripts/verify-installation.sh

Expected result: discovery returns JSON and the verification script completes without reporting a failure.

5

Sign In To The Development Tenant

Use these development-only credentials:

  • admin@mrwho.local / Admin123!
  • Admin UI: https://localhost:8443/admin/clients
  • OidcDemo: https://localhost:5001
  • RazorClient: https://localhost:5003
  • ReactOidcClient: http://localhost:5173
  • TestApi health: https://localhost:7149/health
6

Optional Contributor Workflows

Choose these only when you need them.
