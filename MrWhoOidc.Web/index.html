OpenID Connect and OAuth 2.0 on .NET

Identity infrastructure you can evaluate without reverse-engineering the setup.

MrWhoOidc provides a standards-based identity provider with multi-tenant administration, modern protocol support, and public deployment assets. For first-time public evaluation, use the Docker path, bootstrap the first tenant once, then verify tenant-scoped discovery.

Deployment guide Public repository

First local install

The public happy path is explicit.

  1. Create `certs/aspnetapp.pfx` with `bash ./scripts/generate-cert.sh localhost changeit`.
  2. Copy `.env.example` to `.env` and set `POSTGRES_PASSWORD`, `CERT_PASSWORD`, `OIDC_PUBLIC_BASE_URL`, and a temporary `BOOTSTRAP_TOKEN`.
  3. Start Docker, call `POST /bootstrap`, then remove `BOOTSTRAP_TOKEN` and re-apply the containers.
  4. Verify tenant discovery, admin redirect behavior, and tenant JWKS.

Modern protocol support

Authorization Code + PKCE, Client Credentials, Device Authorization, Token Exchange, PAR, JAR, JARM, DPoP, CIBA, discovery, and JWKS publication.

Multi-tenant administration

Isolated tenants, client and realm configuration, role and scope management, platform administration, and CLI support.

Docker Compose files, environment templates, scripts, examples, and troubleshooting docs are published in the public repository.

Local Docker evaluation

Use the real first-run flow, not just `docker compose up -d`.

On an empty database, the base public compose path requires an explicit bootstrap before tenant discovery and admin login become useful.

Open README 
git clone https://github.com/popicka70/MrWho.git
cd MrWho

bash ./scripts/generate-cert.sh localhost changeit
cp .env.example .env
# set POSTGRES_PASSWORD, CERT_PASSWORD, OIDC_PUBLIC_BASE_URL
# on a fresh database also set BOOTSTRAP_TOKEN

docker compose up -d

curl -k -X POST https://localhost:8443/bootstrap \
  -H "Content-Type: application/json" \
  -H "X-Bootstrap-Token: ${BOOTSTRAP_TOKEN}" \
  -d '{
    "tenantSlug": "default",
    "tenantName": "Default Tenant",
    "adminEmail": "admin@example.com",
    "adminPassword": "ChangeMeNow123!",
    "adminName": "Administrator"
  }'

# remove BOOTSTRAP_TOKEN from .env, then re-apply
docker compose up -d

curl -k https://localhost:8443/t/default/.well-known/openid-configuration
curl -k -I https://localhost:8443/admin/clients
curl -k https://localhost:8443/t/default/jwks

What to expect

  • The admin URL redirects anonymous users to the tenant login page.
  • The strongest first smoke test is tenant-scoped discovery.
  • After removing `BOOTSTRAP_TOKEN`, `POST /bootstrap` should no longer be available.
