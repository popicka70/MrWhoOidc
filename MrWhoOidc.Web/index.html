Why MrWhoOidc

Built different from heavyweight frameworks.

Standards-First

Every OIDC flow implemented directly against RFC specifications. Full transparency into protocol behavior — not hidden behind opaque abstractions.

Multi-Tenant by Design

Isolated tenants with separate discovery, JWKS, and realm scoping from day one. Not bolted on as an afterthought — it's the foundation.

Your Infrastructure, Your Data

Self-hosted and open-source. Runs on Docker Compose or Kubernetes. All identity data stays on your servers — zero vendor dependency.

Capabilities

Modern identity protocols. Production-ready features.

OIDC & OAuth 2.0 Flows

Auth Code + PKCE, Client Credentials, Device Authorization, Token Exchange, CIBA, Refresh Token Rotation.

Security Extensions

DPoP, PAR, JAR, JARM, back-channel logout with durable outbox, automatic key rotation.

WebAuthn / Passkeys

FIDO2 passwordless authentication with discoverable credentials and platform authenticator support.

Admin UI & CLI

Web-based management for clients, scopes, roles, and users. CLI tool (mrwho-cli) for automation.

Multi-Tenancy & Federation

Tenant isolation, platform admin dashboard, external IdP federation, consent management, audit logging.

Docker & .NET Aspire

Docker Compose deployment, .NET Aspire integration, PostgreSQL persistence, OpenTelemetry observability.

Quick start overview

Up and running in three steps.

1

Clone & Configure

Clone the public repo, generate a TLS certificate, and set up your environment variables.

2

Bootstrap Your Tenant

Start Docker Compose and bootstrap your first tenant with a single API call.

3

Verify & Explore

Check tenant discovery and JWKS endpoints, then log into the Admin UI to manage clients and scopes.
